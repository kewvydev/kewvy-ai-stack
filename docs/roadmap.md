# Incremental roadmap

## Stage 0 — Foundation

Initial content, reference analysis, contracts, templates, index, and questions.
Verify local integrity; no installation in target projects yet.
Keep all stack content in English.

## Stage 1 — Minimal workflow for Codex (implemented)

Python CLI with global snapshot, launcher, core project initialization, state,
seed-only project decisions, preview, conflicts, and one-operation rollback.
Temporary-project tests cover reinstallation, updates, preservation, failures,
and interruption recovery. Native Codex CLI instruction discovery was checked
against a local Responses fixture; model compliance remains untested.
No personal installation or Meritum changes were made during development.

## Stage 2 — Working package

Three skills and the verifier are selected and adapted to Codex. Additional
roles and skills require observed needs and user selection. When working on SDD, choose its engine and stage formality.
Test scenarios and outcomes; do not judge quality solely by the presence of files.

## Stage 3 — Profiles and connections

Confirmed future framework entry points: NestJS, React, Next.js, and Spring Boot,
sharing React content with Next.js. Inspect target project versions before choosing
guidance. Context7 and GitHub definitions are selected; authentication remains pending.
Verify configuration and connections separately. Add CI checks when the provider and scope are selected.

## Stage 4 — Distribution and maintenance

A published package, broader diagnostics, and conservative uninstallation.
Local snapshots, update preservation, and one-operation rollback already exist;
package layout migrations and cross-process locking remain deferred.
Document tested compatibility by client and platform; choose a license and
distribution channel. Add a second client or external memory if they provide
demonstrable value.

## 0.3.0-dev expansion

Selected skill packaging, four technology profiles, task/finding records, native
verifier, and an explicit Context7/GitHub profile are implemented. Native discovery
is checked; remote authentication, framework builds, model behavior, hooks, extra
memory services, publication and deployment remain separate future work.

## 0.4.0-dev expansion

Package SDD in every profile; add the nine selected shared global skills and the
report-only native security-auditor. Preserve existing global skill ownership and
project records, and test prior-release updates, recovery and native discovery.
Skill behavior, real security audits and technical read-only permissions remain
separate from packaging. Hooks, an SDD execution engine and external memory are
not introduced by this expansion.

## 0.5.0-dev project-agent increment

Distribute codebase-explorer/test-engineer per project with native adapters, role
contracts, ownership/conflict protection, update/rollback and discovery checks.
Keep global native agents unchanged and reuse profile tools. Behavioral evaluations
of map quality and test engineering remain separate from installation validation.

## 0.6.0-dev routing correction

Move ODD/records to initialized projects; keep the global catalog optional.
Add three task categories with progressive specialized guidance, retain explicit
skill invocation, and remove routine multiagent/auth-auditor mandates. Preserve
Meritum rules and external skill bodies. Discovery and installer validation do
not replace future behavior and cost measurement on real scoped tasks.


## 0.7.0-dev Bash installation

Replace the Python installation runtime with Bash + jq, add a terminal menu for
existing profiles, and preserve explicit automation commands, ownership, preview,
recovery and project records. Keep schema-1 migration reversible and validate in
disposable locations. Wider OS support and model behavior remain separate work.
